# CampusBites run audit checklist

Five CrewAI roles. A Gemini Manager picks every next step; host rules in `agent_demo/orchestration.py` reject anything out of order. Four specialists do the work test-first. This is a bounded supervisor loop, not CrewAI's `Process.hierarchical`, and the specialists run one at a time.

## Prove a real run

1. `/api/state` → `mode` is `live`. `preview` and `reference` are not model runs.
2. `runs/<id>/summary.json`: `feature_request`, `models`, `llm_call_counts` within `llm_call_caps`, `status`.
3. `spec.md`: the Architect's spec, starting with `FEASIBLE: yes`.
4. `events.json`, in this order:
   - `Acceptance tests written (failing, as expected)` from QA, before any Backend or Frontend write
   - `Real source file written` events with before/after SHA-256 and a patch name
   - `Ran tests after writing` after each developer save (the agent's feedback loop)
   - `QA executed real Node tests`, then `QA report received` (host re-run)
   - `Independent release gate` with all five checks `yes`
5. `manager-decisions.json`: every step has `assign`, `reason`, `allowed` and a state snapshot, ending in `COMPLETE`.
6. Patches: `qa.patch`, `backend-attempt-*.patch`, `frontend-attempt-*.patch`.
7. `release-gate.txt`: TAP output with `# fail 0`.
8. Terminal summary: `python scripts/audit_run.py latest`.

## Release gate checks (no AI involved)

| Check | Why |
|---|---|
| All tests pass | Contract tests (human-written) + acceptance tests (QA-written) |
| Manager closed after QA passed | The manager cannot declare success early |
| QA wrote the tests in this run, unchanged since | Nobody edited the tests to make them pass |
| At least 3 acceptance tests | An empty test file cannot pass the gate |
| Backend and Frontend wrote code | Both halves of the feature came from the agents' tools |

## Not proof

- Moving desks, green badges, the scripted preview.
- **Apply reference**: a hand-written feature copied by a human.
- An agent's message saying tests passed.
- `verify.mjs --reference`: checks the reference feature, not the models.
- Offline wiring checks with a fake model.

## Known limits

- Acceptance tests are written by an AI. They can be wrong or weak; read them. The contract tests and the "must fail first" rule limit this, they don't remove it.
- Guardrails are regex checks plus a 2-second worker limit for the backend. They are not a security sandbox.
- No live Gemini/Groq run has been executed while preparing this repo. Rehearse on your own keys.

## Human-owned release criteria

For STUDENT10 tickets, the release gate also runs `tests/student-discount.independent.test.mjs` (six product-owner checks). The checks are *not* generated by QA; they run in addition to QA tests. `summary.json` contains `independent_discount_gate: true`. Passing QA-generated tests alone cannot mark the student coupon shipped. When a run fails the gate, the storefront keeps model-generated partial features hidden.
